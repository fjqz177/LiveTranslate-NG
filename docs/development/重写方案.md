## 0. 目标与边界

**核心目标**：一套全新、简单无脑的**分发 + 更新全流程**，复用旧仓库绝大多数核心代码。

**范围**：
- 迁移：**核心业务逻辑**（ASR/翻译/采集/模型管理）+ **主界面** + **悬浮字幕** + **OBS 字幕** + **托盘菜单**。
- 全面改造：**分发**、**更新**、**依赖环境**、**GUI**。
- 弃用：旧「运行时补全 torch + 内嵌 uv + engine_runtime 状态机(M-VENV) + build_runtime_variants 全合一 variant + 6 套打包方案」。

**边界**：Windows-only（旧仓已定）。跨平台由 pyappify 限制（未实现非 Windows）。

## 1. 定稿架构（三独立层 + 双 profile 装满）

把「软件源码 / 依赖环境 / 模型」拆成**三件完全独立**的事，正好是 pyappify 原生模型：

| 独立层 | 载体 | 更新/安装方式 | 特点 |
|---|---|---|---|
| ① 软件**源码** | git 仓库 → pyappify clone → `working/` | pyappify **git-tag 秒级增量** | 只换代码，依赖不动 |
| ② **依赖环境** | managed Python + `site-packages`（`python/`） | 首次**一次性 pip 装满**（两个变体） | 装满即用，跨更新持久 |
| ③ **模型** | 数据区 `lt_data/models/` | App 用 `hub_downloader` 从 HF/ModelScope 下载 | 与依赖分离 |
| ④ **变体切换** | cpu ↔ gpu | pyappify **切 profile = 重装 torch 变体** | 换硬件时才发生 |

**两个 Launcher 功能**：
- **更新软件源码** = git-tag 秒级（依赖不变，不触发 pip）。
- **更新依赖 / 彻底切换变体** = pyappify 切 profile（default↔gpu），或显式重装依赖。

**分发形态**：pyappify 双 profile（default=cpu / gpu），每个 = **装满全部引擎依赖**（torch 按变体 + funasr + whisper + base）。App 永不管理引擎——装了就有。

### 4.6 分发与更新（pyappify）
- `pyappify.yml`：
```yaml
name: "LiveTranslate"
icon: "assets/icons/app.ico"
website: "https://github.com/fjqz177/LiveTranslate-NG"
profiles:
  - name: "default"              # ★ 必须命名 default（pyappify 更新硬编码读它）= CPU
    git_url: "https://github.com/fjqz177/LiveTranslate-NG"   # 需 vX.Y.Z semver tag
    main_script: "main.py"
    requires_python: "3.12"
    requirements: "requirements-full-cpu.txt"
    pip_args: "--index-url https://pypi.tuna.tsinghua.edu.cn/simple"   # 镜像可换
    use_pythonw: true
    show_add_defender: true
  - name: "gpu"                 # 可切换的 GPU 变体
    requirements: "requirements-full-gpu.txt"    # torch cu126 + cuda libs
    pip_args: "--extra-index-url https://download.pytorch.org/whl/cu126"
```
- `main.py` shim：
```python
import os, sys
from pathlib import Path

# 数据根指向 pyappify 持久区（working 的兄弟 lt_data），先于任何 import
os.environ.setdefault("LIVETRANSLATE_PORTABLE_DIR", str(Path.cwd().parent / "lt_data"))
sys.path.insert(0, os.path.join(os.path.dirname(__file__), "src"))
from livetranslate.__main__ import main

main()
```
- `requirements-full-{cpu,gpu}.txt`：由 CI `uv export` 生成（见 4.7）。默认(cpu)= base+funasr+whisper；gpu 再加 engine-cuda。
- **更新** = git-tag（pyappify 拉两 tag 间 diff → 换 working/，依赖不动 → 秒级）。依赖只在「切变体/显式更新」时由 pyappify 重装。
- **坏包/回滚**：旧 GitHub Releases 冻结为手动回滚通道；pyappify `--update-to-version` 降级。

### 4.7 uv-export ↔ pip 桥 + 漂移门
- 真值源：`pyproject.toml`（base + engine-* extras）+ `uv.lock`。
- 生成（CI `scripts/build_full_requirements.py`，迁移旧 build_runtime_variants 思路）：
```bash
uv export --extra engine-funasr --extra engine-whisper --no-dev --no-emit-project \
  --python-platform windows > requirements-full-cpu.txt
uv export --extra engine-funasr --extra engine-whisper --extra engine-cuda \
  --no-dev --no-emit-project --python-platform windows > requirements-full-gpu.txt
```
- **漂移门**（CI 保留）：重新 export 与仓库里 commit 的 `requirements-full-*.txt` diff，不一致即失败，保证 pyproject==requirements 永不漂移（此即旧 M-VENV 门的换形）。
- torch cu126：export 产生 `torch==2.11.0+cu126` + nvidia-*；pip 用 `--extra-index-url`（pip_args）解析，纯 PyPI 依赖 continue 走主镜像。

### 4.8 CI 发布
`.github/workflows/release.yml`（对齐 ok-ww，去 synchronize）：
1. **Validate**：uv sync + pytest + ruff + mypy + `--smoke` 门（offscreen + 临时数据根 + exit0 + "Smoke OK"）；清空 secrets 环境变量再跑。
2. **Package**：`uv export` 生成 full requirements（+ 漂移门）；`ok-oldking/pyappify-action` → build_exe_only → **SignPath 免费签名** → build_installers → 逐个签名 setup.exe。
3. **Publish**：softprops/action-gh-release 发 setup.exe(v. default/gpu) + `--smoke` 产物门；`gh workflow run` 触发 mirrorchyan（CN 镜像）。
4. （可选）`build-engine-packs.yml` 或集成到 Package：若默认引擎选 SenseVoice-ONNX，产 `sensevoice-small.onnx` 资产。

## 7. 关键风险与规避
1. **`pip install` 装满依赖的体积与耗时**：CPU ~1.5GB、GPU ~4.5GB 在线下载，镜像加速；首次安装要等。→ 引擎页/安装过程显示进度 + 镜像选择；接受「装满省心」。
2. **pyappify 更新硬编码读 default profile**：依赖只在「切变体/显式重装」重 pip；代码更新时 requirements 不变 → 不触发重 pip，绕开该 bug。
3. **`working/` 会被 `sync_delete_extra_files` 重建**：数据必须路由到 `lt_data`（兄弟目录），`LIVETRANSLATE_PORTABLE_DIR` 解决。
4. **「离线」名不副实**：pyappify 更新/git fetch 强制联网；pip 装机也要联网。发布页声明。
5. **ABI 一致性**：不复活变体 venv 注入，全装进同一 env，无 ABI 匹配问题（torch 与 base 同一 python）。torch 变体由 profile 切换，一次一个。
6. **win32 torch 先于 PyQt6**：全装模型下 GUI 进程不 import torch（worker 才 import），此顺序在 GUI 不再触发；`apply_cache_env`（TORCH_HOME 等）保留，worker 首次 import torch 前调用。
7. **`tests/asr/test_client_process.py` 假引擎注入**：删 pythonpaths 后需改为 spawn 环境注入（PYTHONPATH 或目录式 setup）。唯一有真实改动成本的配套点。
8. **SignPath 首跑需手动建项目/审批**：先手动跑通再交 CI。
